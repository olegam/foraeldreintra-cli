# Endpoint discovery and validation

Verified on 2026-10-01.

The saved username/password session authenticated successfully. All supplied page routes were read through direct HTTP requests, without browser execution. See the README for commands and remaining coverage limits.

The public login form and application bundle were also inspected directly. The observed bundle was `https://nsistatics.m.skoleintra.dk/v5.144.8.10713/javascript/skoleintra.js`.

Confirmed contracts:

- Session reuse can return a SAML form at the shared identity provider. POST its hidden response only to the selected school's `/sso/assertionconsumerservice`; this renews a valid saved session without collecting a password again.
- Home is `{child}/Index`, not the child prefix alone. `NewsItemsFeed.Init` supplies `UrlForRetrievingMoreNewsItems`. Its `/newsitems/showmore` endpoint uses a read-only POST with `pagings` JSON keyed by `data-feed-item-type`; the response supplies `View` and `HasMoreItems`.
- News bodies use `.sk-news-item`, `data-feed-item-id`, `.sk-user-input`, `.sk-news-item-author`, `.sk-news-item-timestamp`, and `.sk-attachments-list`. News overview links lead to `/news/news/{id}`. Archive is `/news/news_archive/1` on this school.
- Message page attribute `data-clientlogic-settings-messageconversationswitharchivefunctionality` contains `Conversations` and `DataProviderSettings`. Message list pagination uses `takeFromRootMessageId`, `searchRequest`, and `filter`. Full thread loads use `threadId`, `takeFromRootMessageId`, `takeToMessageId=0`, and `searchRequest`. Expansion uses `threadId` and `latestMessageId`. Missing bodies can be read by `messageId` through the threadless-message read endpoint. Attachments use `AttachmentsLinks[].HrefAttributeValue` and `.Text`.
- Weekly plan pages embed `data-clientlogic-settings-weeklyplansapp.SelectedPlan`, including `GeneralPlan`, `DailyPlans`, `LessonPlans`, schedule, and attachments. `HistoryData` is a list of read receipts, **not** revision timestamps, and is excluded. Historical `item/class/{week-year}` pages work. `weeklyplansattachment/{planId}/{day}/{filename}` serves originals.
- Calendar configuration is JSON in `NewSkoleIntra.Calendar.Init`. `CalendarModel.EventSources` supplies read URLs, methods, and class parameters. GET queries require numeric Unix-second `start` and `end` (date strings caused HTTP 500). `startDate`/`endDate` are .NET epoch dates. Generated `id` values change between requests; `type` plus `originalId` remains stable. School feed type 6 includes birthdays and must not be interpreted as holidays. The separate holidays page is school-year scoped.
- Document folders use `.sk-documents-content-row`, `data-content-link`, `data-documentid`, `.sk-documents-document-title`, `.sk-documents-owner-column`, and `.sk-documents-date-column`. School folders use `/documents/school/list?folderName=…`; class folders use `/documents/class/folder?folderName=…`. File links use `/documents/{scope}/{id}`; the verified class-file redirect is `/file/parent/school/{id}/{folder}/{filename}`.
- Attachment routes also include `/file/newsfrom/{filename}?newsId={id}` and `/file/ckeditorfiles/view/image?fileName={name}&userUnifiedId={id}`. The editor endpoint serves both images and DOCX files. Required query values participate in stable attachment IDs; ignoring them collapses distinct inline attachments. Query keys and path traversal are validated before any request.
- Forms expose a Vue component's `data-vue-component-data` with an `Items` array, despite not having the older `.sk-l-content` container. Both open and closed arrays are empty on the current account.
- Empty contact book, diaries, photo areas, and holidays use `.sk-no-data-feedback`. External links use `.sk-links-container`.
- Contacts use `/contacts/{students|staff}/cards`, a `usercardpage` setting, and dropdown options that link to individual numeric IDs. Fetch only the chosen card; `.sk-labeledtext-caption` and `.sk-labeledtext-value` provide labeled fields. No contact-directory snapshots are retained.

Live verification included six pins, two news articles, eight paginated home-feed items, seven full message threads, a current and historical weekly plan, recursive school/class folders, calendar feeds, targeted lookup of the selected child's card, and explicit empty states. File checks included PDF, DOCX, JPEG images, and a legacy DOC file parsed with macOS textutil. DOCX extraction found eight embedded media parts. Two consecutive content scans produced no spurious changes; repeated calendar reads were compared after removing transient display IDs.

Unfilled coverage remains explicit: nonempty contact-book/diary/form/photo/holiday adapters, populated archive pagination, and different school/login layouts need additional fixtures.
